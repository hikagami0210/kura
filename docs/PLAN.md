# 初期の実装計画

この文書は初期の検討記録です。実装済みの機能と現在の制約は [README](../README.md)、公開準備の状態は [公開ガイド](RELEASE.md) を参照してください。

## 方針

配布するのは静的ドキュメント。開発者にアプリのインストールを求めない。
標準データ形式はJSON、YAMLは同じ構造を表す任意の入出力形式とする。
構造と値はスクリプトで取得し、LLMは意味の説明・関係候補の補助に使う。

## 1. ビューアー正式化

- 公式MermaidとELKへ描画を移行。簡易SVGの配置処理を廃止する。
- ライブラリの正確なバージョン、ロックファイル、設定を固定する。
- スキーマ・テーブル・関係の出力順を固定する。
- 同一のMermaid定義を表示と書き出しに使う。
- DB全体、スキーマ、選択テーブルと関連先の表示を切り替える。
- SVGのズーム、移動、全体表示を実装する。
- ライブラリとJSONを同梱した単一HTMLを生成する。CDNへの依存をなくす。
- 必要に応じ、固定した実行環境で全体図を事前生成する。
- 多重度はNULL可否と一意制約から決める。論理関係の未確認の多重度は確定扱いしない。
- ローカルHTMLとPagesの両方で動作確認する。

## 2. PostgreSQL取得

- tbls等の既存ツールを評価し、スキーマ取得を再利用する。
- 全スキーマ、複合PK/FK、型、コメント、ビュー等を共通形式へ変換する。
- バージョン、DB所有者、容量、文字コード、照合設定、拡張、設定を取得する。
- ロール、所属、CONNECT、USAGE、SELECT等の実効権限を取得する。
- 直接付与、PUBLIC、継承、SET ROLEを区別し、未評価は未取得として表現する。
- RLS・列単位の権限・接続認証は基本権限から区別する。
- 接続先のバージョンと取得ロールの権限に応じて取得不能を明示する。

## 3. マスターとLLM補助

- 初回は対象テーブル・掲載カラム・フィルター・上限を明示指定する。
- 取得値を変更せず、業務説明を別項目として保持する。
- LLMには許可したメタデータ・マスター・seed・コード・資料のみを渡す。
- 候補と確認済みを区別し、説明や論理関係に根拠を持たせる。
- 人が採用した説明を再生成で上書きしない。

## 4. 継続更新

- 手動またはGitLab CIで生成し、Pagesに配置する。
- リポジトリの設計を文書化する場合は一時DBにTypeORMのマイグレーションとseedを適用する。
- 実環境と一時DBの情報は取得元・日時を明記する。
- ドキュメントの差分が安定するように変動値と定義を整理する。

## 完成判定

- 許可したデータからJSONとHTMLを再生成できる。
- 閲覧時のネットワーク要求なしで、絞り込み、ズーム、移動が動く。
- 同じ定義から同じMermaidを生成できる。
- 権限不足、未取得、論理関係候補を確定情報と混同しない。
- 大きいスキーマで計測し、全体図が重い場合に絞り込みへ移れる。
